מהו ניתוב (
Routing
) ואיך נתב מקבל החלטות?

ניתוב הוא התהליך שבו נתב (

Router
) מקבל חבילת מידע (
IP Packet
) ממשק אחד ומעביר אותה לממשק היציאה המתאים בדרך לשרת או מחשב היעד ברשת אחרת. כדי לעשות זאת, הנתב נעזר ב-טבלת הניתוב (
Routing Table
) – "מפת דרכים" המוחזקת בזיכרון ה-
RAM
שלו.

מבנה הנתונים

אנטומיה של טבלת ניתוב

כל רשומה בטבלת הניתוב כוללת מידע קריטי המאפשר לנתב לדעת לאן להפנות את התעבורה:

1. רשת היעד (
Destination Subnet
): כתובת ה-
IP
ומסכת רשת היעד.
2. הצעד הבא (
Next-Hop IP
) / ממשק יציאה (
Exit Interface
): לאן לשלוח את החבילה.
3. מקור המסלול (
Prefix Code
): מאיפה הנתב למד את הדרך (C=מחובר, S=סטטי, O=OSPF).
4.
AD & Metric
: אמינות המקור ועלות המסלול
[AD/Cost]
.
מנגנון ההחלטה

איך הנתב בוחר נתיב?

כשחבילה מגיעה לנתב, הוא פועל לפי 2 חוקי ברזל נוקשים:

🎯 1.
Longest Prefix Match
(התאמה הספציפית ביותר)
הנתב מעדיף תמיד את הכלל הספציפי ביותר! למשל, אם מגיעה חבילה ל-
10.1.1.5
, והטבלה מכילה נתיב ל-
10.1.0.0/16
ונתיב ל-
10.1.1.0/24
– הנתב יבחר ב-
/24
כי הוא ספציפי יותר!
🏆 2.
Administrative Distance - AD
(מרחק מינהלי)
אם לנתב יש שני מסלולים לאותה רשת בדיוק ממקורות שונים, הוא יבחר במקור עם ה-
AD
הנמוך ביותר (
Static = 1
,
OSPF = 110
,
RIP = 120
).

איך לקרוא את טבלת הניתוב?

לפניך פלט אמיתי מפקודת show ip route בנתב Cisco. העבר את סמן העכבר מעל כל שורה בטבלה כדי לגלות ולפרק את משמעות כל פרמטר ברשומה!

Router# show ip route
Codes: C - connected, L - local, S - static, R - RIP, O - OSPF, * - candidate default
C
192.168.10.0/24
is directly connected,
GigabitEthernet0/0/0

🟢 רשת מחוברת ישירות (Connected Route):

• C: מציג שמקור המסלול הוא חיבור פיזי ישיר לנתב.

• 192.168.10.0/24: כתובת רשת היעד ומסכת סאבנט.

• directly connected: אין הופ נוסף (Next-Hop) בדרך.

• GigabitEthernet0/0/0: ממשק היציאה הפיזי בנתב דרכו יוצאות החבילות.

S
10.2.0.0/16
[1/0]
via
192.168.10.254

🔵 ניתוב סטטי (Static Route):

• S: הוגדר ידנית ע"י מנהל הרשת.

• 10.2.0.0/16: רשת היעד המרוחקת.

• [1/0]: ערך מרחק מינהלי AD=1 (אמין מאוד!) ועלות Metric=0.

• via 192.168.10.254: כתובת ה-Next-Hop (הנתב הבא בתור שאליו תישלח החבילה).

O
172.16.1.0/24
[110/65]
via
10.0.0.2
,
00:14:22,
Gi0/0/1

🔴 נתיב שנלמד דינמית דרך OSPF:

• O: נלמד אוטומטית ע"י פרוטוקול OSPF.

• [110/65]: 110 הינו מרחק מינהלי (AD). 65 הינה העלות הכוללת (Metric/Cost) המחושבת לפי רוחב הפס.

• via 10.0.0.2: כתובת ה-Next-Hop לשליחה.

• 00:14:22: הזמן שחלף מאז שנלמד או עודכן המסלול בטבלה.

• Gi0/0/1: ממשק היציאה המקומי.

S*
0.0.0.0/0
[1/0]
via
203.0.113.1

🟡 נתיב ברירת מחדל (Default Route):

• S*: נתיב סטטי המסומן כנקודת יציאה אחרונה (Candidate Default).

• 0.0.0.0/0: "כל יעד שהוא" - תופס כל חבילה שכתובת היעד שלה לא נמצאה ברשומה ספציפית יותר.

• via 203.0.113.1: כתובת הנתב של ספק האינטרנט (ISP).

ניתוב מוגדר ידנית

ניתוב סטטי (
Static Routing
) ו-
Default Route

בניתוב סטטי, מנהל הרשת מגדיר באופן ידני את הנתיב לכל רשת מרוחקת. פתרון זה מעולה לרשתות קטנות, לקישורי קצה, או להגדרת **

Default Route
(נתיב ברירת מחדל)** המפנה את כל התעבורה הבלתי מוכרת אל האינטרנט.

יתרונות ניתוב סטטי

  • אינו צורך משאבי מעבד וזיכרון בנתב.
  • בטיחות מירבית - אין חילופי הודעות ברשת.
  • שליטה מלאה ומודרכת של מנהל הרשת.

חסרונות ניתוב סטטי

  • אינו קונוורג'נטי - לא משתקם אוטומטית כשתקלה מתרחשת!
  • תחזוקה כבדה ומסורבלת ברשתות בינוניות וגדולות.
  • סכנה גבוהה לטעויות אנוש.

שדרוג מניתוב סטטי לדינמי

למה אנחנו חייבים פרוטוקולי ניתוב דינמיים?

בפרק הקודם למדנו על ניתוב סטטי – הגדרה ידנית של נתיבים. אך מה קורה ברשת בעלת מאות נתבים כשכבל נחתך או שנתב קורס? ניתוב סטטי מחייב את מנהל הרשת לקום באמצע הלילה ולעדכן ידנית את כל הטבלאות. פרוטוקול ניתוב דינמי מאפשר לנתבים "לדבר" זה עם זה, ללמוד את הטופולוגיה אוטומטית, ולחשב מסלול חלופי תוך שברירי שנייה!

פרוטוקולי וקטור מרחק

Distance Vector (DV)

נתב הפועל בשיטה זו מכיר רק את השכנים הישירים שלו. הוא שומע מהם "שמועות" לגבי הרשתות הרחוקות ומאמין להן. הוא אינו מחזיק במפה של כל הרשת.

📐 מטריקה (מדד לבחירת נתיב):
ספירת קפיצות (
Hop Count
). הנתיב עם הכי פחות נתבים בדרך מנצח!
⏱️ עדכונים:
עדכונים תקופתיים מלאים (משדר את כל טבלת הניתוב במרווחי זמן קבועים).
💡 דוגמאות מפורסמות:
RIP, EIGRP
פרוטוקולי מצב הקישור

Link State (LS)

כל נתב בונה מפה מלאה ומדויקת של כל הרשת (כמו

Google Maps
/
Waze
). הוא יודע בדיוק איפה כל נתב נמצא, מה רוחב הפס של כל כבל, ומה מצב הקישורים.

📐 מטריקה (מדד לבחירת נתיב):
עלות (
Cost
) – מחושבת על פי רוחב הפס (
Bandwidth
) של הקישורים. מהיר יותר = טוב יותר!
⏱️ עדכונים:
עדכונים נקודתיים רק כשמתרחש שינוי בטופולוגיה (
Triggered Updates / LSA
).
💡 דוגמאות מפורסמות:
OSPF, IS-IS
